# Single MI210: measured Qwen3.8-27B INT8 + DFlash2 optimization

This is an ongoing performance record, not a claim that 110/120 tok/s has been achieved.
The original measured query5/split32 candidate reached **103.80 tok/s**. Independent
repeats with its preserved compilation cache measured **103.45 / 103.03 / 103.06**.
The before/after repeat produced identical token sequences on all 52 diverse prompts
and zero shared-history top-20 coarsened KL. These are repeatability checks, not a
full-vocabulary fidelity or downstream accuracy evaluation.

## Model and measurement contract

- GPU: one MI210 (gfx90a), 64GB, TP1, 300W cap and 1600MHz memory clock.
- Target: local `Qwen3.8-27B-PTQR-R10S60`, the PTQR export of
  `curvedinf/Qwen3.8-27B-GPTQ-INT8-W8A8-GS128-PTQR`.
- Draft: local `dflash2-ptqr-r1`, the matching PTQR INT8 DFlash2 export.
- Both models use INT8 W8A8 GS128 weights and `int8_block_g128` KV. Residual
  compute remains BF16 and Mamba recurrent state FP32.
- Metric: C1, **48,081 input tokens**, **512 completion tokens**, median of five
  streaming generation estimates **excluding TTFT**. This is not total request
  throughput, and it is not a guarantee on all text profiles.
- Container: Torch `2.13.0+git733fca1`, HIP `7.2.53211`, Triton `3.8.0`.
  Dependencies were inherited from the optimized local image, not upgraded.

## Measured operator combination

1. Gfx90a CK INT8 GEMM dispatch on numerically gated exact M/N/K shapes.
2. INT8 language-model head, FP32-state native GDN and grouped INT8 QK attention.
3. Target verification attention: five query tokens per program, 32 query rows,
   two warps, 64-token KV reads and 32 split-KV partitions.
4. NS13 DFlash2, decoded through GPU graphs with C8 capture capacity.

The local tested image is
`sha256:eb769d7cd65e61b7533013eafe3650e6d3bf06b501da530cadbb752bc1bb0a50`
(`int8-vllm-mi210:query5-candidates-20261007`). This SHA identifies a **local Docker

## Quality limits and rejected candidates

All 52 constrained answer probes and vision smoke checks passed for the 103 tok/s
configuration. Its diverse outputs differ from the older query10 control (5/52
exact sequences, shared-history coarsened KL about 0.0200); downstream fidelity
qualification remains incomplete. It therefore remains a performance candidate.

- NS15 on the original image: **71.91 tok/s**; rejected.
- Register activation quantization: operator values/scales were bit-identical,
  but integration measured **91.31 tok/s**, below the best. Its controls changed
  outputs between runs (82.87/79.83 tok/s), so an isolated model speedup cannot
  be claimed. All 16 concurrent answers and all three 120K retrieval probes
  passed in those experiments. Candidate image and containers were deleted
  after archiving results; the code was reverted.
- KV read tile128: numerically passed, but only **0.47–0.65x** the current
  attention operator speed. Candidate image deleted; code reverted.
- Native Gluon GEMM prototype: all numerical gates passed, but slower than tuned
  CK on every tested real shape; not integrated.

The attention geometry screen measured KV32/split32 **83.85 tok/s**,
KV64/split16 **74.97 tok/s**, and KV32/split64 **75.93 tok/s**. Although
KV32/split32 was 1.26x faster in the isolated operator test and passed
ragged/128K replay gates, model speed fell as draft acceptance and generated
text changed. These combinations were rejected; the original 64/32 geometry
remains the best measured configuration. The final control repeat and
separate AMD lazy-rescale prototype are still in progress.
